## Functional requirements

### Connections
- On launch nothing is connected and there is no default connection: the Explorer, Publish and Charts screens show an empty state with "Choose a connection" until a profile is connected. The active connection is the last one connected or the one chosen in the connection bar.
- Connection bar (owner, 13 Oct 2026, change set 2): a tab strip under the title bar lists every open connection (connected, connecting, reconnecting) with its name, a status dot, short live figures (topics, messages per second, negotiated version) and a ✕ that disconnects it. Clicking a tab opens the Explorer on that connection and marks the tab active. The bar is always shown (owner, 15 Oct 2026, change set 8): the rail runs from the title bar to the bottom of the window, and the bar is the first row of the main column to the right of the rail, never the full window width. With no open connection the strip is empty: no text, no button (owner, 15 Oct 2026, change set 9; the "Choose a connection" hint of change set 8 is gone). The figures on a tab (topics, messages per second) are smoothed: the rate is a one-second average refreshed once a second, written "312 msg/s", never a value that jumps at every render (change set 9). There is no title bar pill any more (owner, 13 Oct 2026, change set 4): the title bar holds the app name and the app mark only. The rail carries the state instead: the Broker icon shows a small play badge in the accent colour while the broker runs (clay while it starts), nothing when it is stopped; the Connect icon shows a small round count bubble (accent background, white figure) with the number of open connections (connected, connecting, reconnecting) and nothing when none is open. A connection that accepts the broker's certificate without verification, or by a pinned fingerprint, shows a ⚠ warning icon with a tooltip explainer on its tab in the connection bar and on its card (owner, 14 Oct 2026, change set 6; the clay "unverified" chip is gone); "anonymous" lives on the Broker screen only (the "restart pending" chip is gone, change set 7).
- The Connections screen is the home screen. It lists profiles as cards of three lines (owner, 14 Oct 2026, change set 6): the name with the state word and the play or stop button; one chip, left aligned, with the protocol (mqtt, mqtts, ws, wss; accent tone for mqtts and wss, clay for mqtt and ws; the abbreviation "mTLS" never appears in the app, owner, 13 Oct 2026), followed by the ⚠ warning icon when this connection skips verification or pins a fingerprint; the host (name or IP, no prefix) and the port as "host:port" in monospace. Nothing else: version, subscriptions, last used and the meta line are gone. Cards are a little taller than before (padding 13 px, 4 px between lines). A connected profile's card is filled with the accent colour and reads "connected" top right, followed by a round stop button (■, tooltip "Disconnect") that disconnects this connection and nothing else, never the broker (owner, 13 Oct 2026, change set 4); a reconnecting one is outlined in clay, reads "reconnecting" and carries the same stop button, which cancels the retries. A connecting card shows "connecting" with the stop button too. An idle card (not connected) shows, in the same place, a round play button (▶, tooltip "Connect") that connects this profile, starting the embedded broker first when the profile is "Local broker"; play and stop never show together (owner, 14 Oct 2026, change set 5). A profile opens in the right pane for editing; "Connect" opens the Explorer. Connecting the profile "Local broker" (from the header button, the card menu, the first-launch card or the palette) starts the embedded broker first when it is stopped (card state "starting broker…", then "connecting"), then connects; "Test" does the same. If the broker cannot start, the connection fails with the broker's reason (owner, 13 Oct 2026, change set 4).
- Card context menu (right-click or the ⋯ key): "Connect" or "Disconnect" (depending on the state), "Test", "Duplicate", then "Delete…" which asks for confirmation (name shown; "Delete" and "Cancel"). The form header holds "Delete" (outlined in brick, same size as the other buttons), then "Test" and "Connect"; the Duplicate button is gone from the header, it lives in the menu only. Deleting a connected profile disconnects it first.
- The profile "Local broker" follows the embedded broker (owner, 13 Oct 2026): any broker change that affects it (its listener's kind, port or reachability; the client-certificate requirement; a CA rotation; the mqtt-panel password; Anonymous) updates the profile at once; if it was connected it reconnects at once when its own listener or login changed, and stays connected when the change does not touch it (change set 7: nothing restarts).
- The form groups fields into Basics (always open), a "Security" fold and an "Advanced" fold that holds Session, Subscriptions and Decoders as sub-headings (owner, 13 Oct 2026, change set 4). Both folds are closed when the app starts; their state is kept while the app runs. A fold header shows a chevron, the title and a muted one-line summary of what is set inside, empty when everything is at its default: Security "CA · client certificate" (the "Verify server" switch is gone since change set 6, the skip switch sits under Advanced); Advanced "keep-alive 60 s · 3 subscriptions · 1 schema", plus "skip verification" in clay when that switch is on. Security shows a green "verified" or clay "unverified" state in its summary once a test connection ran. Rows carry labels, controls and ⓘ bubbles only; the short helper sentences that sat next to the controls ("System roots plus the CA below.", "Only if the broker serves several names.", "Some cloud brokers require it.") are gone, their content lives in the ⓘ.
- Basics holds, in this order (owner, 14 Oct 2026, change set 5): Name; "Protocol" (segmented mqtt / mqtts / ws / wss); "MQTT version" (3.1.1 / 5 / auto) on its own row under it; "Host and port"; "WebSocket path" (ws and wss only); Client ID; Username; Password. The former "Transport" row that held both segments side by side is gone. FR « Protocole » and « Version MQTT », DE „Protokoll“ and „MQTT-Version“. The Client ID row's button reads "Generate" (FR « Générer », DE „Generieren“; "Random" until change set 6, owner, 14 Oct 2026).
- Text fields do not stretch to the pane width (owner, 14 Oct 2026, change set 6). Every text input has one of four widths: S 80 px (ports, seconds), M 160 px (paths, tags), L 240 px (client ID, username, password, SNI, last will), XL 320 px (name, host field, file fields); the label column stays at 170 px so left edges align. The rule holds in every form of the app (connection form, Broker dialogs, Settings); editors, the payload area and search boxes are not fields.
- A new profile takes its name from the host (owner, 14 Oct 2026, change set 6): while the user has not typed a name, the Name field follows the host field with the first label of a host name ("myhost" for myhost.com, "broker" for broker.plant.example), the address itself for an IP ("10.20.4.17", "::1") and "localhost" for localhost. Name stays an ordinary field: editing it breaks the link and the typed name stays; clearing it restores the link. Existing profiles are never renamed.
- Address prefiller (owner, 14 Oct 2026, change set 5): the host field always starts with the protocol's prefix ("mqtt://", "mqtts://", "ws://" or "wss://"), followed by the host and, once the user typed one, ":port". Choosing a protocol rewrites the prefix and keeps the rest; the port box switches to the new protocol's default (1883, 8883, 8083, 8084) when it still held the previous default, and the suffix follows. Typing or pasting a prefix in the field selects that protocol ("tcp://" counts as mqtt, "ssl://" and "tls://" as mqtts; case does not matter). Typing ":<number>" after the host sets the port box; editing the port box rewrites the ":port" suffix in the field. A pasted full address such as "wss://demo.emqx.example:8084/mqtt" sets protocol, host, port and, for ws and wss, the WebSocket path in one go. IPv6 literals keep their brackets ("[::1]:1883"). The profile stores scheme, host, port and path as separate fields as before: the field is a view; a prefix the user deleted comes back when the field loses focus, and the protocol stays as it was.
- With Protocol mqtt or ws the Security fold is disabled (owner, 14 Oct 2026, change set 5): its header is greyed, it cannot be opened, and in place of the summary it reads "Not encrypted: choose mqtts or wss to use certificates." (FR « Non chiffré : choisissez mqtts ou wss pour utiliser des certificats. », DE „Nicht verschlüsselt: Wähle mqtts oder wss, um Zertifikate zu verwenden.“). The values inside (verify, CA, certificate, key, SNI, ALPN) stay in the profile and come back when the protocol returns to mqtts or wss. The former warning line "Certificates only apply with mqtts or wss." is gone.
- "New connection" is a menu, not a button (owner, 13 Oct 2026, change set 1): "New broker…" (FR « Nouveau broker… », DE „Neuer Broker…“; "Another broker…" until change set 6) opens the empty form; "Built-in broker" (FR « Broker intégré », DE „Eingebauter Broker“; "This app's broker" until change set 5, "MQTT Panel broker" until change set 6, owner, 14 Oct 2026) opens a submenu with "Use an existing listener" and "Add a listener…". The words "this app's broker" and "MQTT Panel broker" appear nowhere else either: the dialog title reads "Connect to the built-in broker" (FR « Connexion au broker intégré », DE „Mit dem eingebauten Broker verbinden“); cards have no meta line any more. The form has no Target row any more; the menu decides. Wording stays free of jargon (owner, 12 Oct 2026: no "custom" or "embedded"). The first-launch card "New connection" opens the same menu; the card "Start a local broker" opens the "Built-in broker" dialog directly. The first-launch screen has these two cards only: the import card is gone (change set 5).
- Import from other tools is not offered in the UI (owner, 14 Oct 2026, change set 5): the "Import" line under the list, the drop zone on the list, the welcome card "Import from other tools", the native menu entry and any palette entry are gone. The import code (engine command, file formats, summary dialog) stays in the codebase and keeps its crate-level tests; the scope table (X2) lists it as a later feature.
- "Built-in broker" dialog (mockup 02b, title "Connect to the built-in broker"): a list of the broker's listeners, the most secure one preselected (TLS with client certificates, then TLS, then secure WebSocket, then TCP, then WebSocket); a listener row reads "TLS · port 8883" with the chip "client certificate" when the broker requires one, never "mTLS" or "Mutual TLS", or "Add a listener…" which runs the Add listener flow (mockups 13 and 14) first. The dialog states in one paragraph what the app will do: create the user "mqtt-panel" with a strong generated password (kept if it already exists, password in the keychain), issue the client certificate "mqttpanel-desktop" when the listener requires one (re-issued when revoked or superseded), trust what the broker serves: its local CA, or, after a server certificate from another issuer was imported, that issuer's CA from the import, or the served certificate pinned by fingerprint when the import had no CA, start the broker when it is stopped, then connect. One primary button "Connect". While it runs, the dialog shows the steps ticking off; an error stops the list with a plain-words reason. With Anonymous on, no user is created and the dialog says so. The result is always the single profile "Local broker" (host localhost, port and scheme of the listener, verify server on, CA, client certificate, username, password reference, MQTT 5), updated in place, never duplicated, and the Explorer opens on it. Nothing restarts in this flow: a listener added here starts at once (change set 7).
- The profile's test button is labelled "Test" (FR « Tester », DE „Testen“; owner, 13 Oct 2026).
- Form rows never wrap: labels, helper texts and chips stay on one line (owner, 12 Oct 2026). Helper text is short; the full explanation lives in the ⓘ bubble. SNI and ALPN are separate rows labelled "Server name (SNI)" and "Protocol tag (ALPN)". Keep-alive and session expiry are separate rows.
- Subscriptions: a new profile starts subscribed to everything, shown as the chip "# · QoS 0" with the hint "everything". Each filter chip carries an X to remove it; removing the last one leaves the profile with no subscriptions and a visible notice ("No subscriptions: you will see nothing until you add one"). Info bubble: "Filters decide which topics this connection receives. # means everything; building/+/temperature means one level of wildcard."
- Info buttons (owner, 19 Oct 2026, change set 11): every ⓘ in the app is the same round button, a circle of 18 px with a thin muted outline and an "i", never the pill-shaped chip; it opens the bubble as before.
- Certificate and key fields are file pickers, never typed paths: a Browse button opens the native file dialog (PEM, CRT, KEY, PFX, P12) and a file can be dropped onto the field. After the Browse button the row states the accepted formats in muted text, exactly what the picker filters: CA certificate "PEM, CRT, DER", client certificate "PEM, CRT, DER, P12, PFX", client key "PEM, KEY" (owner, 19 Oct 2026, change set 11). Next to the file name the app shows nothing else but a plain error when the file is not what the field expects, such as "This file is not a certificate" (owner, 13 Oct 2026, change set 4: the parsed chips "until 2031-03", "CN=…" and "Keychain" were too much; the "Keychain" chip next to the password is gone too). Keys and PKCS#12 passphrases still go to the secret store on import; the ⓘ says so.
- The password field has an eye button that reveals the typed or stored password while pressed, for every profile (owner, 19 Oct 2026, change set 11); the copy icon stays reserved for passwords the app generated.
- Client certificate, two exclusive ways (owner, 19 Oct 2026, change set 11): a segmented control at the top of the Security fold, under the CA certificate row which always stays, with "Import certificate and key" and "Generate key and request a certificate". Import is the form known so far (client certificate, client key, PKCS#12 passphrase when needed). Generate has three steps on one card: "Generate key" (ECDSA P-256 by default, RSA 2048 as a second choice; the key goes to the secret store, the row then reads "Key generated · ECDSA P-256" with its fingerprint), "Download CSR…" (common name prefilled with the client ID, editable; native save dialog, PEM .csr) and "Import signed certificate…" (Browse, PEM, CRT, DER; a certificate that does not match the generated key is refused with "This certificate does not match the generated key"); "Start over" discards the key and certificate after a confirmation. Switching the segment while the other side holds material asks "Discard the imported certificate and key?" / "Discard the generated key?" and clears it on Yes. The fold summary reads "CA · client certificate (imported)" or "CA · client certificate (generated key)". Every step has an ⓘ.
- Session expiry shows a plain field with the unit "s" and no hint (owner, 19 Oct 2026, change set 11: "0 = none" is not UI text); its ⓘ says: "How long the broker keeps your session after a disconnect: subscriptions and queued messages. Empty or 0: the session ends with the connection."
- Every security field has an info bubble in plain words, in EN, FR and DE.
  - CA certificate: "The certificate of the authority that signed the broker's certificate. Needed when the broker uses a private or self-signed certificate; leave empty for brokers with a public certificate."
  - Client certificate: "Identifies this computer to the broker, instead of or in addition to a password. Only needed if the broker requires client certificates."
  - Client key: "The private key belonging to the client certificate. Stored encrypted by MQTT Panel, never in the profile file." followed by where the master key lives in this build (change set 10): "On this build, the key that protects your saved passwords and keys is in a file only your user account can read." (unsigned builds) or "The key that protects your saved passwords and keys is in the system keychain." (signed builds).
  - Server name (SNI): "The host name sent to the broker during the TLS handshake. Leave empty to use the host above; only change it if the broker serves several names on one address."
  - Protocol tag (ALPN): "Tells the broker which protocol is wanted over TLS. Some cloud brokers require a specific value (for example mqtt); leave empty otherwise."
- "Test" performs CONNECT and DISCONNECT and reports the result in plain words. When the broker's certificate cannot be verified (self-signed, unknown CA, expired, name mismatch, or a pinned fingerprint that changed), Connect and Test open the certificate prompt (mockup 03; owner, 14 Oct 2026, change set 6): title "This broker's certificate cannot be verified", the reason, the certificate (subject, issuer, SAN list, validity, fingerprint, key), one risk sentence ("Without verification, anyone between you and the broker could pose as it and read or change your messages.") and a list of choices with one primary button "Connect": "Trust this certificate" (preselected; this certificate only, for this connection, pinned by its fingerprint; a different certificate asks again), "Skip verification only this time" (this attempt accepts any certificate, nothing is saved), "Skip verification always for this connection" (saved in the profile: any certificate is accepted whenever this connection opens) and, only when the chain ends in a private CA certificate, "Trust anything this CA signs" (fills the profile's CA field). Every choice is for this connection only, never for the whole app; the app-wide "Skip verification" setting is gone. Owner feedback 12 Oct 2026 still holds: the choices are listed with one sentence each, not as a row of similar buttons.
- Under Advanced, Session, the switch "Skip unverified broker certificate" with an ⓘ (FR « Ignorer le certificat non vérifié du broker », DE „Ungeprüftes Broker-Zertifikat zulassen“; change set 6). Turning it on opens the prompt "Skip the broker certificate check?" with the risk sentence and the choices "Only this time" and "Always for this connection" (and Cancel): "Always" saves the switch on; "Only this time" leaves it off and marks the next connection attempt of this profile, shown as the muted words "next connection only" next to the switch until that attempt. Turning it off needs no prompt. The ⓘ: "Accepts any certificate this broker presents, even an expired, self-signed or impostor one. Use it only on a network you trust, for a broker you cannot give a CA or a fingerprint for." The "Verify server" switch that sat under Security is gone; this switch is the one control.
- The ⚠ icon on cards and tabs (change set 6) has a tooltip: with verification skipped, "Certificate verification is off for this connection: any broker certificate is accepted, so an impostor could not be told apart." (FR « La vérification du certificat est désactivée pour cette connexion : n’importe quel certificat est accepté, un usurpateur ne serait pas détecté. », DE „Die Zertifikatsprüfung ist für diese Verbindung aus: Jedes Broker-Zertifikat wird akzeptiert, ein Angreifer wäre nicht zu erkennen.“); with a pinned fingerprint, "You trusted this broker's certificate by its fingerprint; it could not be verified against a CA." (FR « Vous avez accepté le certificat de ce broker par son empreinte ; il n’a pas pu être vérifié par une autorité. », DE „Du hast das Zertifikat dieses Brokers über seinen Fingerabdruck akzeptiert; es konnte nicht gegen eine CA geprüft werden.“). The icon is clay for a skipped check and muted for a pinned fingerprint.
- Errors from the broker (CONNACK reason codes in MQTT 5) are shown with the code and its meaning.
- Several profiles can be connected at the same time. The connection bar switches the active one (change set 2; the ⌘⇧L switch menu remains; the rail's count bubble shows how many are open, change set 4); the Explorer, Publish and Charts screens are scoped to the active connection. Each tab in the bar always shows the negotiated protocol version (MQTT 3.1.1 or MQTT 5), which may differ from what the profile asked for when "auto" is set.

### Explorer: tree and table
- Tree rows (owner, 15 Oct 2026, change set 8), left to right: the twisty and the last segment of the topic; right after the name, the last payload on the width available (monospace, one line, truncated with an ellipsis), with the small "R" retained marker after it; then, right-aligned, the sparkline, the message count since connect, the throughput written with its unit ("5 msg/s", change set 9: a one-second average refreshed once a second, so the figure does not flicker) and, at the end, the number of subtopics (topics below this one, shown as the small grey counter). The four right-hand items sit in fixed columns shared by every row (sparkline, messages, rate, subtopics), right-aligned, so they line up vertically down the tree; a row without a sparkline or without subtopics leaves its column empty (owner, 15 Oct 2026, change set 9). Each of the three figures has a tooltip: "Messages since the connection opened", "Messages per second", "Subtopics below this one". The age text ("2 s", "14 min") is gone; activity shows through the throughput and the new-message highlight. The sparkline is the last 10 values of one tracked value of the topic, never the message rate; hovering it shows the values with their times.
- Sparkline rule (owner, 15 Oct 2026, change set 8): when the payload is a bare castable number or boolean-like text, the sparkline follows that value on its own. When the payload is JSON (or anything structured), nothing is drawn until the user picks a value: clicking a key or a value in the Payload view opens the click menu with "Use as sparkline" (plus "Add to chart…", "Copy path", "Copy value"; a text field shows "Use as sparkline" disabled with "text, not plottable"). One sparkline per topic: picking another value replaces it. The pick is saved with the profile per topic, and the sparkline uses the same history the engine keeps for every numeric field. A right-click on a sparkline offers "Hide sparkline", which switches it off for that topic (saved with the profile as well); the topic context menu then offers "Show sparkline" to bring it back, and a new "Use as sparkline" pick brings it back too (change set 9).
- Nodes are collapsed by default. Expand options: this node, to depth n, all changed in the last minute. Expansion state is saved with the view.

### Assistant (MCP)
Summary of `docs/MCP.md` sections 2, 3 and 6 (validated by the owner on 20 Oct 2026; phases 1 and 2 implemented 20 Oct 2026).
- **What it is.** An assistant (Claude Desktop, Claude Code, the ChatGPT desktop app, any MCP host) works in the running app through MCP tools: it lists, creates, fixes, tests and connects connections, handles certificates and moves the view. The user sees every change in the window.
- **Transport.** The running app owns a local socket for the current user only: `mcp.sock` in the app data folder (mode 0600) on macOS and Linux, the named pipe `\\.\pipe\mqttpanel-mcp-<user>` on Windows. Nothing listens on the network; there is no HTTP endpoint. A host starts `mqttpanel mcp` or the app's own executable with the single argument `mcp`; that shim forwards stdio to the socket and starts the app (in the background) when it is not running, waiting up to 20 s. Enabled by default. ChatGPT on the web is out of scope (it only reaches remote HTTPS servers).
- **One-time acknowledgement.** The first time a host connects, and on Settings, Assistant, the app shows once: "Over this interface an assistant can change everything in MQTT Panel, including deleting connections, retained messages and broker settings. You stay in control of what you ask it." with Accept and Not now. Until accepted, tools that change something answer "Not yet allowed: accept the acknowledgement in MQTT Panel, Settings, Assistant." (a call waits up to 60 s for the answer); reading tools work. No confirmation per tool call; the host's own permission prompts stay the user's gate.
- **Secrets.** Every tool that takes a password, a key, a passphrase or a certificate file has `ask_in_app` (default true): MQTT Panel opens its own prompt or file picker (Browse… and drag-and-drop) and the call waits up to 120 s for the user; the secret never passes through the chat. The direct way (the value as an argument) works, says in its description that the value travels through the chat transcript and the model provider, returns that warning once per host session and is noted "secret given through the assistant" in the log. No tool result ever contains a password, a private key or a passphrase.
- **Audit.** Every writing call shows a toast ("Assistant: Connected Plant broker (MQTT 5).") and adds a row to the Assistant log: time, assistant (the host's own name), tool, arguments with secrets as •••, outcome (done, refused, failed, cancelled, no answer). Kept until the app quits, never on disk; Clear and Export… (text file through the save dialog); also the resource `mqttpanel://assistant-log`.
- **Limits.** One host session at a time: a second one gets "Another assistant is connected to MQTT Panel." Calls time out after 30 s, `connect` after 20 s, calls that wait for the user after 120 s.
- **Language.** Results, errors, prompts and the log follow the app language (EN, FR, DE); tool names and descriptions are English for the model.
- **Tools shipped (phases 1 and 2).** Connections: `list_connections`, `create_connection`, `update_connection`, `set_connection_password`, `set_ca_certificate`, `set_client_certificate`, `generate_client_key`, `get_client_csr`, `import_signed_certificate`, `test_connection`, `trust_certificate` (pin, ca, skip_once, skip_always), `connect`, `disconnect`, `delete_connection`. Navigation: `show_connection`, `show_topic`, `show_chart`, `show_broker`, `show_settings`; they bring the window forward without taking the keyboard from another app and a toast says "The assistant moved the view." Resources: `mqttpanel://connections`, `mqttpanel://assistant-log`. Prompts: "Connect me to a broker", "Why can't I connect?". Broker, data and chart tools follow in phase 3.
- **Settings, Assistant.** Rows, each with its round ⓘ: Acknowledgement (accepted date or Accept), Connected assistant, Claude ("Add to Claude": writes the entry `mqttpanel` into the Claude Desktop and Claude Code configuration files that exist, after a confirmation naming them, then reports which were written), ChatGPT ("Add to ChatGPT": writes `[mcp_servers.mqttpanel]` into `~/.codex/config.toml`, created if missing, for the ChatGPT desktop app), Other hosts (the JSON snippet with Copy configuration), Assistant log (table, Export…, Clear). Both buttons keep everything else in the files.
