## Functional requirements

### Connections
- On launch nothing is connected and there is no default connection: the Explorer, Publish and Charts screens show an empty state with "Choose a connection" until a profile is connected. The active connection is the last one connected or the one chosen in the connection bar.
- Connection bar (owner, 13 Oct 2026, change set 2): a tab strip under the title bar lists every open connection (connected, connecting, reconnecting) with its name, a status dot, short live figures (topics, messages per second, negotiated version) and a ✕ that disconnects it. Clicking a tab opens the Explorer on that connection and marks the tab active. The bar is shown only while at least one connection is open. There is no title bar pill any more (owner, 13 Oct 2026, change set 4): the title bar holds the app name and the app mark only. The rail carries the state instead: the Broker icon shows a small play badge in the accent colour while the broker runs (clay while it starts), nothing when it is stopped; the Connect icon shows a small round count bubble (accent background, white figure) with the number of open connections (connected, connecting, reconnecting) and nothing when none is open. A connection with server verification skipped shows a clay "unverified" chip on its tab in the connection bar and on its card; "anonymous" and "restart pending" live on the Broker screen only.
- The Connections screen is the home screen. It lists profiles as cards with name, address line with the security chip (TLS, WSS, no TLS; the abbreviation "mTLS" never appears in the app, owner, 13 Oct 2026), version, subscriptions and last used. A connected profile's card is filled with the accent colour and reads "connected" top right, followed by a round stop button (■, tooltip "Disconnect") that disconnects this connection and nothing else, never the broker (owner, 13 Oct 2026, change set 4); a reconnecting one is outlined in clay, reads "reconnecting" and carries the same stop button, which cancels the retries. A connecting card shows "connecting" with the stop button too. A profile opens in the right pane for editing; "Connect" opens the Explorer. Connecting the profile "Local broker" (from the header button, the card menu, the first-launch card or the palette) starts the embedded broker first when it is stopped (card state "starting broker…", then "connecting"), then connects; "Test" does the same. If the broker cannot start, the connection fails with the broker's reason (owner, 13 Oct 2026, change set 4).
- Card context menu (right-click or the ⋯ key): "Connect" or "Disconnect" (depending on the state), "Test", "Duplicate", then "Delete…" which asks for confirmation (name shown; "Delete" and "Cancel"). The form header holds "Delete" (outlined in brick, same size as the other buttons), then "Test" and "Connect"; the Duplicate button is gone from the header, it lives in the menu only. Deleting a connected profile disconnects it first.
- The profile "Local broker" follows the embedded broker (owner, 13 Oct 2026): any broker change that affects it (its listener's kind, port or reachability; the client-certificate requirement; a CA rotation; the mqtt-panel password; Anonymous) updates the profile at once, and if it was connected it reconnects after the restart.
- The form groups fields into Basics (always open), a "Security" fold and an "Advanced" fold that holds Session, Subscriptions and Decoders as sub-headings (owner, 13 Oct 2026, change set 4). Both folds are closed when the app starts; their state is kept while the app runs. A fold header shows a chevron, the title and a muted one-line summary of what is set inside, empty when everything is at its default: Security "verify on · CA · client certificate" or "verify off"; Advanced "keep-alive 60 s · 3 subscriptions · 1 schema". Security shows a green "verified" or clay "unverified" state in its summary once a test connection ran. Rows carry labels, controls and ⓘ bubbles only; the short helper sentences that sat next to the controls ("System roots plus the CA below.", "Only if the broker serves several names.", "Some cloud brokers require it.") are gone, their content lives in the ⓘ.
- "New connection" is a menu, not a button (owner, 13 Oct 2026, change set 1): "Another broker…" opens the empty form; "This app's broker" opens a submenu with "Use an existing listener" and "Add a listener…". The form has no Target row any more; the menu decides. Wording stays free of jargon (owner, 12 Oct 2026: no "custom" or "embedded"). The first-launch card "New connection" opens the same menu; the card "Start a local broker" opens the "This app's broker" dialog directly.
- "This app's broker" dialog (mockup 02b): a list of the broker's listeners, the most secure one preselected (TLS with client certificates, then TLS, then secure WebSocket, then TCP, then WebSocket); a listener row reads "TLS · port 8883" with the chip "client certificate" when the broker requires one, never "mTLS" or "Mutual TLS", or "Add a listener…" which runs the Add listener flow (mockups 13 and 14) first. The dialog states in one paragraph what the app will do: create the user "mqtt-panel" with a strong generated password (kept if it already exists, password in the keychain), issue the client certificate "mqttpanel-desktop" when the listener requires one (re-issued when revoked or superseded), trust the broker's own CA in the profile, start or restart the broker when needed, then connect. One primary button "Connect". While it runs, the dialog shows the steps ticking off; an error stops the list with a plain-words reason. With Anonymous on, no user is created and the dialog says so. The result is always the single profile "Local broker" (host localhost, port and scheme of the listener, verify server on, CA, client certificate, username, password reference, MQTT 5), updated in place, never duplicated, and the Explorer opens on it. Restarts in this flow happen without the restart prompt.
- The profile's test button is labelled "Test" (FR « Tester », DE „Testen“; owner, 13 Oct 2026).
- Form rows never wrap: labels, helper texts and chips stay on one line (owner, 12 Oct 2026). Helper text is short; the full explanation lives in the ⓘ bubble. SNI and ALPN are separate rows labelled "Server name (SNI)" and "Protocol tag (ALPN)". Keep-alive and session expiry are separate rows.
- Subscriptions: a new profile starts subscribed to everything, shown as the chip "# · QoS 0" with the hint "everything". Each filter chip carries an X to remove it; removing the last one leaves the profile with no subscriptions and a visible notice ("No subscriptions: you will see nothing until you add one"). Info bubble: "Filters decide which topics this connection receives. # means everything; building/+/temperature means one level of wildcard."
- Certificate and key fields are file pickers, never typed paths: a Browse button opens the native file dialog (PEM, CRT, KEY, PFX, P12) and a file can be dropped onto the field. Next to the file name the app shows nothing but a plain error when the file is not what the field expects, such as "This file is not a certificate" (owner, 13 Oct 2026, change set 4: the parsed chips "until 2031-03", "CN=…" and "Keychain" were too much; the "Keychain" chip next to the password is gone too). Keys and PKCS#12 passphrases still go to the secret store on import; the ⓘ says so.
- Every security field has an info bubble in plain words, in EN, FR and DE.
  - CA certificate: "The certificate of the authority that signed the broker's certificate. Needed when the broker uses a private or self-signed certificate; leave empty for brokers with a public certificate."
  - Client certificate: "Identifies this computer to the broker, instead of or in addition to a password. Only needed if the broker requires client certificates (mutual TLS)."
  - Client key: "The private key belonging to the client certificate. Stored in the OS keychain, never in the profile file."
  - Server name (SNI): "The host name sent to the broker during the TLS handshake. Leave empty to use the host above; only change it if the broker serves several names on one address."
  - Protocol tag (ALPN): "Tells the broker which protocol is wanted over TLS. Some cloud brokers require a specific value (for example mqtt); leave empty otherwise."
- "Test" performs CONNECT and DISCONNECT and reports the result in plain words. On a self-signed or unknown-CA certificate it says "This broker presents a certificate MQTT Panel cannot verify." and shows the certificate (subject, issuer, SAN list, fingerprint, expiry) with one action for a self-signed certificate: "Trust this certificate", with the scope stated in one line underneath ("This certificate only, for this profile. If the broker presents a different one, you are asked again."). Only when the presented chain ends in a private CA certificate does a second button appear, "Trust anything this CA signs", with its own scope line ("future certificates from this CA too"); it fills the profile's CA field. Owner feedback 12 Oct 2026: two similar options were confusing. Connect, not only Test, offers the same prompt the first time.
- Errors from the broker (CONNACK reason codes in MQTT 5) are shown with the code and its meaning.
- Several profiles can be connected at the same time. The connection bar switches the active one (change set 2; the ⌘⇧L switch menu remains; the rail's count bubble shows how many are open, change set 4); the Explorer, Publish and Charts screens are scoped to the active connection. Each tab in the bar always shows the negotiated protocol version (MQTT 3.1.1 or MQTT 5), which may differ from what the profile asked for when "auto" is set.

### Explorer: tree and table
- Tree rows show the last segment, a child count, the last value inline (truncated, monospace), a retained marker, an activity dot (changed in the last 10 s) and an optional sparkline of the last 10 cast values of the topic (the same series as the chart: value, never message rate; the rate is shown as text, "5 msg/s"). Hovering the sparkline shows the 10 values with their times.
- Nodes are collapsed by default. Expand options: this node, to depth n, all changed in the last minute. Expansion state is saved with the view.
- New-message highlight: when a message arrives on a topic, its row flashes briefly and settles to the activity dot; every collapsed ancestor shows the same highlight, so activity deep in a collapsed branch is visible at the top. The highlight respects reduced motion (no flash, dot only).
- Message count since connection: every node shows, discreetly next to the child count, how many messages it and its subtree received since the connection was opened. It resets on reconnect and with Clear history, and is one of the sortable columns in the table view.
- Table view lists leaf topics flat. Columns can be shown, hidden, reordered and sorted. The same search and filters apply to both views, and switching views keeps the selection. "Value · last 10" is a sparkline of the cast value; the message rate is the separate Rate column.
- Search supports plain text, MQTT wildcards (+, #) and regex (prefix /). Filters: retained only, changed in the last n minutes, payload contains, QoS.
- Pinned topics appear as chips above the tree and as a group at the top of the table. Pinning is per view. Views are saved per profile and listed in a drop-down with "Default".
- Selecting a topic opens the detail pane. Follow mode keeps the detail pane on the live message; pause freezes it and shows the number of messages missed.
- Quick publish: the detail pane has a one-line publish row under the topic name: payload field (format follows the last message, overridable), QoS, retain and Send. It publishes to the selected topic and logs to the Sent log like any other send. "Publish here" still opens the full composer for anything longer.
- Context menu on a topic: Pin, Publish to this topic, Add to chart, Copy topic, Copy payload, Copy as CLI, Export subtree, Delete retained, Delete retained in subtree, Clear history.

### Message inspection
- Detail pane tabs: Payload, Diff, History, Chart, Properties.
- Payload format is detected (JSON, UTF-8 text, binary, image, Sparkplug B by topic namespace, CBOR and MessagePack by content type or heuristics, Protobuf where a schema is assigned) and can be forced.
- Protobuf: .proto files (with their imports) are added per profile; each is assigned to one or more topic filters with a message type. Matching payloads are decoded to JSON for the payload, diff and chart views; decode errors show the raw bytes and the reason.
- Diff highlights added, removed and changed JSON keys and values; for text, a line diff. Any history entry can be chosen as the baseline.
- Pick a field straight from the payload (owner, 12 Oct 2026): right-click, or the chart icon shown on hover, on any key or value in the Payload and Diff views offers "Add <field> to chart", which opens the field picker with that field checked (numeric and boolean fields can be added in one step), plus "Copy path" and "Copy value". On a text field the chart item is shown disabled with "text, not plottable".
- History lists the buffered messages for the topic; selecting one shows it in Payload and Diff. The buffer size is shown and can be raised for this topic alone.
- Properties shows the negotiated protocol version first, then the MQTT 5 properties when present and the standard fields (QoS, retained, dup, size, receive time).

### Publish
- Publish is a top-level screen with three parts: Templates (left), Composer (centre), Sent log (right column). The "Send ⌘↵" button sits top right in the composer header, like "Connect" on the Connections screen (owner, 13 Oct 2026); "Send and clear", repeat and "Delete retained…" stay at the bottom of the composer.
- The composer has topic (autocomplete from the active connection's known topics), QoS, retain, format, payload editor with syntax highlighting and validation for JSON, and a collapsible MQTT 5 properties section (content type, payload format indicator, response topic, correlation data, message expiry, user properties as key-value rows).
- One-off is the default: sending never creates a template. A send produces a sent-log entry only. A template exists only when the user chooses "Save as template" from the composer or from a sent-log row, and names it. The Templates pane has no "New" button; the composer is always the starting point and has a Clear action.
- The simple case needs no setup: pick the topic from the autocomplete (or "Publish here" from a topic in the Explorer), format Text, type `1` or a short string, Send.
- Send keeps the composer content, so repeated sends with small edits are fast. "Send and clear" is a secondary option.
- Delete retained is a separate, clearly labelled destructive action in the composer that sends an empty retained message to the topic after a confirmation.
- Repeat publish: interval in seconds, optional count, a visible running indicator and a stop control; stops automatically on disconnect.
- Sent log rows show time, topic, size, QoS, retain flag and status (sent, acked, failed, with the reason). Actions: re-send, load into composer, save as template, copy as CLI command. The log holds the last 500 entries per connection and can be exported.
- "Publish to this topic" from the Explorer switches to Publish with topic, last payload and format prefilled.
- The Request and response section carries an ⓘ bubble (owner, 12 Oct 2026): "Request and response is an MQTT 5 feature. Your message carries a response topic and a correlation ID. The device answers on that response topic and copies the correlation ID into its reply. MQTT Panel subscribes to the response topic for you, matches the reply by correlation ID and shows it next to the sent entry. Broker and device must both speak MQTT 5; on 3.1.1 this section is not available."
- Request and response (MQTT 5 only): the composer can set a response topic and correlation data; MQTT Panel subscribes to the response topic and shows the reply next to the sent-log entry, matched by correlation data, with the round-trip time. On a connection that negotiated MQTT 3.1.1 the section is hidden and replaced by one line: "Request and response needs MQTT 5; this broker negotiated 3.1.1." Nothing half-works.

### History and charts
- A series is one topic plus one field (JSON path), never the whole payload. The engine records history for every numeric and boolean field automatically, so a field picked later already has its past values, but a chart shows only the fields the user picks (owner, 12 Oct 2026). "Add to chart" (context menu, Chart tab, Charts screen) opens a picker listing the fields found in the last message with a checkbox each, nothing preselected, showing last value and cast rule; text fields are listed greyed as not plottable; a path can be typed for nested or absent fields; the target chart is chosen in the picker. Boolean-like text (true/false, T/F, on/off, yes/no, 1/0, case-insensitive) becomes 0/1 and is drawn as a step series. The Chart tab shows the charted fields as removable chips.
- The Charts screen holds one or more charts; each chart has series (topic plus field), a shared time range (last 5 min to session, or custom), a pause control and a hover readout. Every series card is editable in place (owner, 12 Oct 2026): name, topic, field path, colour from the palette, style (line, step, points), axis (left or right), unit, and Remove. The field can be typed as a path or picked by clicking a key or value in the last message of that topic, shown under the field: numeric and boolean fields are clickable and write their path into the field, text fields are greyed with "text, not plottable". The typed path remains for fields absent from the sample. Series with different units can be placed on left and right axes. Charts themselves can be renamed, duplicated and removed.
- History is in memory for the session. Disconnecting keeps it; closing the connection or the app clears it after a prompt if an export has not been made.
- Export: a chart as CSV (time, one column per series) or PNG; a topic or subtree as CSV, JSON or NDJSON with a time range picker and a size preview.

### Broker
- The Broker screen (reorganised 13 Oct 2026, change set 4, owner: too cluttered) shows in the left pane: the status tiles (Status with uptime, ↓ Messages in, ↑ Messages out, Retained; no Clients tile, the right pane lists them), Listeners, then two boxed panels, Users and Client certificates, then the fold "▸ Advanced security" closed by default. The right pane shows Clients (header "Clients", no count, no "live" word) and, at the bottom, the log strip "▸ Log" with "· n warnings" only when n > 0; clicking the strip expands the full log with the level filter (mockup 12c); the state is remembered. Clients and log update live; there is no Refresh button. Every explanation on this screen lives in an ⓘ bubble; nothing explanatory is shown permanently.
- Client certificate requirement is one setting for the whole broker (owner, 13 Oct 2026): "Client certificates on encrypted listeners: Optional / Required", with "Verify against: Local CA / Imported CA", both inside the "Advanced security" fold with an ⓘ bubble each (change set 4; the sentence "Every device needs its own certificate, issued here, before it can connect." is in the ⓘ, not on the row). The listener rows do not show it; the "Encrypted + client certificates" preset sets it to Required. Authentication keeps Anonymous and the users table. Start, Restart and Stop are at the top; there is no "Connect Explorer here" button any more (the Connections screen owns that flow).
- Restart prompt (owner, 13 Oct 2026): a change that needs a restart (listener added, removed, switched on or off, kind, port or reachability changed; certificates changed) immediately asks "Restart the broker to apply the change?" with the body "Listener changes take effect after a restart. Connected clients are disconnected for a moment and reconnect on their own if they are set up to." and the buttons "Restart now" and "Later". "Restart now" saves and restarts. "Later" keeps the change pending: the Restart button turns into a pulsing clay button labelled "Restart broker and apply changes" until it is pressed; with reduced motion it is highlighted without pulsing. The pending state survives navigation and is visible as the "restart pending" chip on the Listeners line. Changes that apply live (users, anonymous) never prompt.
- Setup presets are offered only when adding a listener, never as a standalone block, so a beginner meets them in context. "Add listener" step 1 asks for the setup, with an info bubble per choice; step 2 asks kind and port only (change set 4: reachability is broker-wide and the certificate rows are gone; no login row: users are shared, change set 1). Choosing a setup configures that listener and the shared certificates and authentication it needs (for example, Mutual TLS turns on the local CA and "require client certificate" for that listener). Presets: Plain, lab only (TCP, anonymous, labelled unencrypted); Encrypted (local CA and server certificate); Encrypted + passwords; Encrypted + client certificates (server certificate and client certificates issued here; FR « Chiffré + certificats clients », DE „Verschlüsselt + Client-Zertifikate“; the name "Mutual TLS" is gone, owner, 13 Oct 2026). A preset can be adjusted afterwards without losing the explanation.
- Ports: defaults 1883, 8883, 8083 and 8084; each listener's port is editable, limited to 1024 to 65535. A value below 1024 is refused with "Ports below 1024 need administrator rights; choose 1024 or higher." A port in use shows which process holds it when the OS allows, otherwise "already in use".
- Reachability is one choice for the whole broker (owner, 13 Oct 2026, change set 4: no per-listener switch): a segmented control on the Listeners line with the two choices "This computer only / Whole network" (FR « Cet ordinateur seulement / Tout le réseau », DE „Nur dieser Computer / Ganzes Netzwerk“; no label words, the ⓘ next to it explains), default Whole network (all interfaces, 0.0.0.0 and ::) so devices on the network can connect without extra steps. The explanation is in its ⓘ bubble only, never a permanent strip: "Whole network: any device that can reach this computer can connect, subject to the users and certificates below. This computer only: programs on this computer only." Changing it needs a restart (restart prompt). The listener table has the columns On, Kind, Port, Setup and an ✕ button that removes the listener at once (the restart prompt follows; no ⋯ menu, no confirmation); a plain listener while Whole network is chosen shows the small "unencrypted" chip after its kind.
- Client certificates are a boxed panel: header "Client certificates" with an ⓘ ("Export a certificate as PEM or PKCS#12 and install it on the device together with CA.pem."), the primary button "Issue…" and "Import CSR…"; the table has the columns Name, Expires, Last seen, then the actions PEM, PKCS#12 and ✕ (revoke, asks for confirmation because it cannot be undone); the certificate used by the profile "Local broker" carries a muted "Local broker" tag instead of ✕ (change set 4). "Issue…" asks for a name (client ID or device), issues it from the local CA and offers PEM or PKCS#12 export with a passphrase. The passphrase field has an ⓘ bubble (owner, 12 Oct 2026): "Protects only the exported file (the PKCS#12 bundle or the PEM key). It is not the broker login and not a listener password. The device asks for it once, when the certificate is installed." The issued list shows name, issued date, expiry, last seen (connected, time ago, never) and actions: export PEM, export PKCS#12, revoke. "Import CSR" signs a request generated on the device so its private key never leaves it. Revoked certificates are refused at the next handshake.
- "Advanced security" is a fold closed by default (state kept while the app runs) under the two panels. It holds, as plain form rows with ⓘ bubbles: "Client certificates" with the choice Optional / Required followed by the muted words "on encrypted listeners", "Verify against: Local CA / Imported CA", and "Broker certificates": the local CA and the server certificate as one line each (name, valid until, key type) with the actions Export CA.pem, Import…, Regenerate… and Rotate CA…. - Info bubbles: every security option has a short explanation in plain words, written for someone who is not a TLS specialist. - First start generates a local CA ("MQTT Panel Local CA") and a server certificate for localhost and the machine's hostname. Defaults: ECDSA P-256 keys, CA valid 5 years, server and client certificates 2 years. The user can regenerate with custom SANs or import their own files.
- One broker, several ports (owner, 13 Oct 2026): there is one shared set of users for all listeners and no per-listener login. ### Settings
