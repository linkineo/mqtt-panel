Basics, in this order: Name, Protocol, MQTT version, Host and port, Client ID, Username, Password; "Security" and "Advanced" (Session, Subscriptions, Decoders) are folds closed when the app starts, their header line summarising what is set inside (02d shows them open). The host field always starts with the protocol's prefix and mirrors the port box: choosing ws writes "ws://", typing "mqtt://" selects mqtt, ":1884" at the end sets the port box and the port box rewrites the suffix; a pasted full address fills everything. Cards have three lines: the name with the state and the play or stop button; one protocol chip (mqtts and wss in the accent, mqtt and ws in clay) with a ⚠ icon when the connection skips verification or pins a fingerprint (tooltip explains); host and port. A connected card is filled with the accent colour and carries a round stop button that disconnects this connection only, never the broker; an idle card carries a round play button in the same place that connects it. Connect on "Local broker" starts the broker first when it is stopped. Text fields have fixed widths and align on the label column; a new profile is named after its host until the user types a name. "New connection" is a menu: "New broker…" opens the empty form; "Built-in broker" leads to "Use an existing listener" or "Add a listener…" (02b).

One list, one Connect button (change set 6): pin the certificate (preselected, the safest), skip the check for this attempt, or skip it always for this connection; when the broker presents a chain ending in a private CA, a fourth choice "Trust anything this CA signs" fills the profile's CA field. Privacy

MQTT Panel collects nothing. There is no telemetry, no crash reporting and no account. The app makes no network calls except to the brokers you configure. Passwords, keys and passphrases are stored in the system keychain.
