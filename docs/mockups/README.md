# Validated mockups

`mqtt-panel-mockups.html` is the implementation reference for the user interface: twenty-seven screens and states (change set 1 of 13 Oct 2026 added 02b and 12c; change set 2 of 13 Oct 2026 added 02c and edited 02, 04 to 11, 12, 12c, 13, 14, 18 and 19; change set 4 of 13 Oct 2026 added 02d, removed the title bar pill from every screen, added the rail badges and reworked 02, 02b, 02c, 12, 12b, 12c, 13, 14 and 17; change set 5 of 14 Oct 2026 added 02e and reworked 01, 02, 02b, 02c, 02d, 03 and 19; change set 6 of 14 Oct 2026 reworked 02, 02b, 02c, 02d, 02e, 03, 17 and 19; change set 7 of 14 Oct 2026 removed every restart element from 02b, 12, 12b, 12c and 14), validated by the owner on 12 Oct 2026. Open it in any browser; it is self-contained (no network, no external fonts). The header switches light, dark and the three accents.

Rules the mockups encode and the app must follow:
- Labels in plain words, never jargon in user-facing text.
- Form rows never wrap; helper text is short and the full explanation sits in an ⓘ bubble.
- Every file field is a native picker with drag-and-drop; nobody types a path.
- Every security option has an info bubble in plain words (EN, FR, DE).
- Window chrome, menus, dialogs and scrollbars are the native ones of each OS; the two menu-bar strips in the file are samples.

The app's screens are compared against these mockups in the visual regression suite.
